# 本轮设计判断：自然的电话 + 清爽的页面

2026-10-31。前端这一轮。Codex 把"开口即打断"做成了真的能力（thinking / speaking / transcribing 阶段，本人一开口就停旧声、保留这句开头继续听；静音和暂停时不打断）。界面要跟着改的不是多加一句说明，而是**把原来替后端兜底的说明文字删掉**。

## 一、打断从"说明"变成"反馈"

原来的电话房间有三处在教人怎么打断：启动卡的前言、每个阶段的 hint、大按钮下的小字。现在打断不需要教了，于是：

- **删掉启动卡上那段前言**（`CALL_PREFACE` 只留给读屏器，说清会请求麦克风权限这件有后果的事）。"打电话"是公认的隐喻，真正的门槛是浏览器的权限弹窗，不是文案。
- **运行中的阶段不再写 hint**。hint 只保留在真有需要的四处：接通（权限）、静音（它听不到你）、暂停（麦克风关上了）、出错（文字都还在）。
- **"插话"从主角降为备用**。它继续在中间那一格、继续可按、继续能被 Tab 走到，但不再用最重的深色样式喊"必须点我"。
- 新增**打断成功的无字反馈**：检测到 `speaking/thinking/transcribing → listening` 且 `heardSpeech` 为真时，面包那条字幕退成虚线+淡色（它的话被切断了，不是凭空消失），同时听的光环亮起来，约 1.1 秒。读屏器那边没有视觉，所以给一句 `停下来了，在听你说`。
  - 判据用 `heardSpeech`：一轮正常说完也会回到 `listening`，但那时还没听到人声。拿不到这个信号就什么都不显示——不假装打断成功。
- **一次性提示**：本次通话里面包第一次开口时，状态下方出现一行 `想说就直接开口，也可以点"插话"`，约 5 秒后消失，本次通话不再出现；本人真的开口打断了就立刻收掉。新能力只披露一次，不复述。

## 二、把"更快"做在感知上

前端改不了模型速度，但能不再往等待里加噪音（Templeton 2022 的推断：少做无用的串行等待，也不为快抢话）。

- `transcribing` 和 `thinking` 在界面上**合并成同一句**「嗯，让我想想」。它们是实现细节，一秒内换两次标题只会让人觉得机器在忙自己的事。字符串一样 ⇒ 不重排、不重播报。
- 顶部那行从「正在接通 / 通话暂停中 / 和面包语音中」收成一个不会变的「语音通话」+ 计时。状态由大标题和脉冲点的颜色说，一处一次。
- 等待时屏幕上留着的是**你刚说的那句**（`lastHeard`），不是"我在""稍等"的循环安慰（Weger 2014 的推断：贴住具体内容，不套用咨询句式）。

## 三、身份与数据说明：一个清楚的入口，不在主流程重复

AI 身份的入口是名字旁边那枚 `AI` 印章（首页、顶栏、通话中顶栏都在，一按就是"关于"）。所以：

- 通话房间里那行「AI 网页里的语音对话，不是电话线路」删掉——和顶栏的印章重复，而且它原先在 720px 以下被 `display:none`，等于手机上本来就没有。印章不会消失，这反而更可靠。
- 首页页脚的免责声明、陪伴角落的「没有真人值守…」、对话顶部分隔线里的「面包是 AI…默认不保存」都删掉。
- 收进"关于"的：不做心理诊断、默认不保存的完整规则、打电话的真实机制**和它的边界**（直接开口打断不保证在任何环境下都准，所以"插话"一直在）。宣传不写进主界面，边界也不写进主界面——两者都在同一页可主动查看。

## 四、通读四个页面后的减法

留下的标准：**出错说明、设备状态、会丢东西的提醒、按钮自己的名字**。删掉的：括号补注、"你可以…"、重复第二遍的规则、给自己辩解的话。

- 首页：删页脚免责声明；三个"不用…"的提示行删掉（占位符已经示范了）；三条"换一种开始"的副标题各留一句要紧的（`不会打开麦克风` 这种设备事实留着）。
- 对话：分隔线只说「今晚的对话从这里开始」；念稿时的「上面的文字就是字幕」、思考时的「想好、核对过才会…」、开场白后的「听完想说就说…」删掉；`停止` 按钮就在顶栏且有名字。
- 录音/转写：每个阶段的解释句压到一句或零句，按钮名字已经承担了语义。
- 结束页：保留"这张卡片没留下会消失"和"两种都会开始新的一段"——这两条防的是真的意外丢失，不是防御自己；其余压短。
- 危机提示（`support_guidance`）不削弱，只去掉末尾那句"停止、结束随时都可以用"。

## 五、窄屏、长字幕、字号、reduced motion

- 删掉顶部那行 AI 说明，等于给 320 宽的屏幕退回一行高度。
- hint 不再预留固定行高（原来是 `min-height: 1.7em`）：没有 hint 的阶段把这点空间让给字幕，不会和控制键挤到一起。
- 面包的长字幕继续是"限高 + 内部滚动"，加 `scrollbar-gutter: stable`，字号放到特大时不跳；你那句继续夹到两行。
- 打断反馈刻意**不用 keyframes**，只用 opacity / 边框这类静态属性切换 1.1 秒。`prefers-reduced-motion` 会把动画和过渡时长压到接近 0，但终态照样生效——所以减少动态的人也看得到"它停下来了"，不是只有动画的人才看得到。
- 三个键的位置、数量、大小在任何阶段都不变（静音 | 主键 | 挂断）。通话里按错键的代价太高，不给它机会重排。

## 不做的事

不加面向用户的模型/音色/参数设置；不显示延迟数字或"已优化"之类的说明；不把论文、阶段原理、疗效写到主流程；不声称任何噪声或设备下都可靠。

## 续接（同日，额度中断后）

### 六、短暂状态的寿命归它自己管

Codex 接入时指出：`caught` 和 `cue` 的 timeout 挂在 `[phase, heardSpeech]` / `[phase]` 的 effect 里，下一次阶段变化会先清掉 timeout，而状态还开着，于是"被切断"的样子或那句提示可能一直留着。现在：

- 触发归触发：阶段 effect 只负责 `setCaught(true)` / `setCue(true)`。
- 寿命归寿命：独立的 `[caught]`、`[cue]` effect 各自起停 1.1 秒 / 5.2 秒的 timeout。重复触发时状态已是 true，不会叠加计时。
- 提示再加一道门：只在 `transcribing/thinking/speaking` 里显示。静音或暂停时"想说就直接开口"是错的，宁可不说。
- 字幕：打断 speaking 时后端保留 caption，那条字幕按 `is-cut` 淡去；打断 thinking/transcribing 时 caption 已清空，没有可淡去的东西，只由光环和标题表达。不为这种情况造一条假字幕。

### 七、文字回复失败：一个动作，放在出事的地方

v12 的 VM 有 `canRetry` 和 `retryLastTurn()`。设计判断：

- **重试按钮贴在那句没回上的话下面**（你那一侧，右对齐）：`这句还没回上来 · 再试一次`。失败属于这句话，不属于屏幕底部的一个通用提示；手机上 toast 正好压在输入框上方，离那句话最远。
- **面包自己的那句话按实际状态说**。原来统一的"出了点小问题，打字还能用"在文字请求失败时恰恰不对（打字本身就是失败的那条路）。现在 `canRetry` 时说 `刚才那句没回上来。`，其它错误只说 `刚才出了点问题。`——不承诺什么还能用，具体原因由错误提示说。
- 按下后按钮会因为开始生成而消失，焦点移到页面标题（`preventScroll`，不弹手机键盘），不会掉到 `<body>`。
- 通话中不显示（通话有自己的"再试一次"）；`busy` 时不显示；状态变了 `canRetry` 由后端置 false，按钮自然消失。

### 八、关于页：机制和边界写准，只写在这里

打电话一栏改为：不是运营商线路、无真人接听；接通后按停顿自动转写、回复、念出；面包在想或在说时也在这台设备上留意新的声音，开口即停、开头保留；吵的环境、外放或蓝牙可能听错漏听，所以"插话"一直在；静音、暂停、挂断后麦克风不再采集。回复服务没接好时不再说"打字照样可以"（那时打字也没有回复）。删掉"核对格式和引用后才显示"这句无法在低延迟链路上确认的说法。

### 九、给 Codex 的接线说明（请合并时保留）

1. `components/vm.ts` 给 `BreadVM` 加了可选的 `canRetry?` / `retryLastTurn?`。`domain/view-model.ts` 已声明为必选时，交叉类型自动收紧为必选，无需改动。
2. 重试入口改在对话里（`SessionView → Conversation`）。**建议 `BreadApp` 不再把 `canRetry/retryLastTurn` 透传给 `Notices`**，否则同一次失败会出现两个"再试一次"。`Notices` 上已加的可选 props 保留无害；本任务文件里的 `BreadApp.tsx` 没有这段透传，按本版合并即可。若你们判断 toast 里仍需要（例如对话区不可见的场景），请在对话里的按钮可见时隐藏 toast 的那一个。
3. `SessionView` 的 aria-live 已按本机修复写入：`[activity, inCall]`，进入 idle 清空。挂断、新卡片的播报 effect 声明在它之后，同一次提交里仍会覆盖为最新消息。
4. `CallRoom` 的 `[caught]` / `[cue]` 独立寿命已落实，和本机修法等价；判据仍是"从可打断阶段回到 listening 且 700ms 内 `heardSpeech` 为真"。

### 十、核对：哪些真正落实了

已落实（源码里能找到）：
- 一：启动卡前言改为仅读屏（`CALL_PREFACE` + `sr-only`）；运行阶段无 hint；"插话"`soft` 样式、同尺寸同位置；打断反馈 `is-caught` / `is-cut` + 读屏播报；一次性提示。
- 二：转写/思考同一标题；顶栏"语音通话"+计时；等待时显示 `lastHeard`。
- 三：通话房间 AI 说明行、首页页脚、陪伴角落、对话分隔线里的身份/存储句均已删；"关于"已补全。
- 四：首页、对话、录音/转写、结束页、顶栏提示文字的减法；危机提示保留主体。
- 五：hint 不预留行高；长字幕 `scrollbar-gutter: stable`；打断反馈只用静态属性；三键不重排。
- 六至八：如上。

仍需 Codex 在真实环境验证：
- 打断判据在真实设备上是否总能拿到 `heardSpeech`（拿不到时只是不显示反馈，不会误报）；700ms 窗口是否需要按实测调整。
- 物理麦克风、外放、蓝牙下的误打断与漏打断（本轮界面不对此做任何保证）。
- `canRetry` 的时机：失败后按钮出现、重试中消失、状态变化后不再出现；重试不重复记录用户那句。
- 320×700、特大字号下：错误提示 + 长字幕 + 三键同时出现时不遮挡；对话里重试行换行正常。
- 读屏：打断时播报"停下来了，在听你说"一次；文字失败时重试行被 log 区域读出一次，且不与 toast 重复两遍"再试一次"。
