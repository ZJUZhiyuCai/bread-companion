# 从开源项目到面包：语音上传与动效

2026-11-05。基线 `3e4ad81`。本轮保留 DeepSeek Flash、现有同理心提示词、MiniMax HD 温暖闺蜜及完整回复校验；改动集中在上传、可观测性和浏览器渲染。

## 采用了什么，为什么

| 项目 / 一手资料 | 对面包有用的经验 | 本轮处理 |
| --- | --- | --- |
| [Mediabunny](https://github.com/Vanilagy/mediabunny)、[Ogg 输出](https://mediabunny.dev/guide/output-formats) | 复用成熟编码与封装工具，处理编码器延迟、帧与容器边界 | 固定 `mediabunny@1.65.1`；浏览器原生 Opus 64 kbit/s 单声道，独立 Worker 编码，库负责 Ogg 封装与服务端解包 |
| [Pipecat 延迟观察器](https://github.com/pipecat-ai/pipecat/blob/main/src/pipecat/observers/user_bot_latency_observer.py) | 以用户说完到实际开始播放为总延迟，并拆出各阶段；取消回合不能污染下一轮 | 沿用真实浏览器端到端测量；ASR 响应增加上传/解析与准入耗时，和已有 provider / total 并列，只含数值 |
| [LiveKit 的轮次调优](https://docs.livekit.io/agents/logic/turns/tuning/) | 结束判断、打断与预生成需要一起评估；预生成会增加取消后的无效计算 | 保留现有打断与轮次控制。当前 MiniMax 接口在完整上传后返回转写，尚不具备安全提前生成的输入条件；没有盲目缩短静音等待或增加付费并发 |
| [Motion 性能指南](https://motion.dev/docs/performance) | 优先 transform/opacity，避免持续布局与重绘，真实测量浏览器行为 | 保留原生 CSS / View Transitions；Claude 将常驻呼吸移到 HTML 外层，减少 SVG 内循环和不必要模糊。没有为简单过渡另加动画运行库 |

没有整套迁移 Pipecat 或 LiveKit：目前的 Next.js、准入限制、来源版本和取消链仍有效。完整 WebRTC + 流式 STT 是后续可验证的架构选项，需要另外测移动端网络、断线重连、成本和实体设备。

## 上传通道与回退

通话开始时后台准备编码器；未准备好时直接上传 WAV，不等下载。编码超过 **250 ms**、不兼容、失败或没有明显缩小时，仍只发一次原始 WAV 请求。挂断和打断终止编码，迟到结果不能启动上传。编码不碰模型与语音输出，也不改变识别后的用户控制流程。

服务器只接受一个完整 Ogg/Opus 单声道流，限制字节数、页数、包数、实际包时长和容器时长；超过 65 秒、拼接多流、截断、伪造时长等在调用 ASR 前拒绝。仍使用原来的超时、配额与至多一次顺序 ASR 恢复。

维护者可设置 `BREAD_OPUS_UPLOAD=off` 停止向新客户端公告压缩能力。旧客户端继续使用 WAV；支持 Opus 的已打开页面仍可完成请求。客户端没有使用第三方 CDN。

Mediabunny 保持原库不修改。其 MPL-2.0 与面包的 MIT 代码分别保留；[许可与对应源码](../public/licenses/mediabunny.txt)。

## 实测与边界

### 上传与识别

同一段合成语音分别上传 WAV 和浏览器编码的 Opus，在候选服务调用真实 MiniMax。三组输出逐字一致，包括否定表达与“不想听建议”的偏好。没有上传用户录音。

| 合成片段 | WAV | Opus | 上传体积减少 | 转写文字 |
| --- | ---: | ---: | ---: | --- |
| 1.35 秒短句 | 43,244 B | 11,303 B | 73.9% | 相同 |
| 准备一个月后被拒，今晚不想听建议 | 220,664 B | 55,718 B | 74.7% | 相同 |
| 不是想放弃，只是累了，别替我分析 | 186,360 B | 45,049 B | 75.8% | 相同 |

三组原生编码约 23–55 ms。候选服务器本机 ASR 请求分别为 WAV **1112/865/986 ms**、Opus **519/776/733 ms**，这个顺序测试也受连接预热与服务波动影响，不能把差值全部归因于压缩。输入音频是有损编码；这三段的一致性不能代表所有口音、噪声或否定表达。原始记录见 [候选链路验证](design-motion/asr-preflight.json)。

改动前主站三轮浏览器等待 **8.116 / 8.969 / 4.061 秒**；其中一次转写总请求 5.272 秒，MiniMax 处理约 0.647 秒。进一步服务器本机三次转写 **0.870 / 0.607 / 0.600 秒**。这支持减少上传负担，但不代表文字模型长尾已经消失。

### 动效

Claude 的原始 [诊断](design-motion/DIAGNOSIS.md) 和 [实现说明](design-motion/IMPLEMENTATION.md) 保留。Codex 修正了资源请求失败也可能被判断为图片就绪的问题：只有图片实际具有像素时才移除五官遮罩。原稿哈希见 [原稿记录](design-motion/original-sha256.json)。

本机 Chrome，在首屏稳定后取五秒窗口：390px / 1440px 的布局次数由 **93 / 90 → 0 / 0**，总主线程任务时间约 **49 / 46 → 32 / 31 ms**。这是短窗口诊断，不是帧率承诺，眼睛反光等离散动作仍会更新。两个尺寸均无横向溢出、页面错误；转场后写话框保持焦点。

验证包括类型检查、生产构建、**302 项单元/集成测试**、原有 **63 条浏览器流程**，以及新增 **4 条**：两轮 Opus 通话、不支持编码的 WAV 回退、照片迟到、照片失败与减少动态。测试包括真实 Worker、原生编码器、AudioWorklet 和播放链；常规 E2E 的模型/转写接口是 Mock。实体鸿蒙/微信、iOS、蓝牙与外放效果尚未复测。
