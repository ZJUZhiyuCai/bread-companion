# 毛绒形象与红色电话 · 0.2 验收

2026-10-31。本轮由官方 Claude Code 设计前端，Codex 完成后端、素材接入和验证。原稿与接入修正见 [溯源](living-companion-provenance.json)，设计判断见 [设计稿](design-living-companion.md)。

## 已实现

- 原创毛绒身体加分层玻璃眼睛：注视、眨眼、摸头反馈、说话与倾听姿态。目光来自指针、焦点和应用状态，不使用摄像头或推断用户情绪。
- 红色转盘座机就是拨号入口。连接期间转盘转动，实际开始播放后听筒抬起；没有为了动画增加等待时间。暂停、失败与挂断跟随真实状态。
- 默认 MiniMax 温暖闺蜜的固定开场：“喂，我是面包。我在呢，慢慢说。”音频已提前生成，本地提供；配置不匹配时调用对应 TTS，文件缺失最多回退一次。普通聊天不缓存。
- 开场准备期间也可开口打断。挂断会取消准备与播放，迟到的权限、文件或模型结果不再进入已结束通话。
- 本地拨号音在用户点击后创建，麦克风开始监听前停止；不会把本机拨号音当成用户开口。
- Codex 修复 320 px 下气泡遮住电话的问题，保留 Claude 设计；小屏改为独立布局行。摸面包不抢输入焦点。通话画面宽度过渡也限制在容器内，修复从桌面切到竖屏时的短暂横向滚动。

本机完成类型检查、生产构建、**155 项单元/集成测试、24 条不同浏览器流程**。浏览器测试分为完整 23 条回归与新增/修改的 3 条针对性复核；部分用例重复执行，不重复计数。CI 会从干净 checkout 执行全部流程，状态见 [main checks](https://github.com/ZJUZhiyuCai/bread-companion/actions/workflows/ci.yml)。

覆盖缓存开场、不同音色、静态文件缺失、重复点击、挂断后迟到音频、权限拒绝/迟到、静音、后台暂停、自然插话、转写/模型取消、回声和噪声误触发、设备释放，以及已有材料、卡片、保存、导入导出。新增检查验证实际音频播放时听筒旋转、连接期间转盘动画和小屏遮挡。

人工查看 1440×1000 桌面、320×700 小屏、390×844 深色界面和接通画面。320/375/390 px 无横向溢出、气泡不遮电话；指针左右移动会改变目光；减少动态时循环动画缩为单次极短状态变化，保留文字状态。自动无障碍检查沿用 Chromium + axe，不能替代读屏真机测试。

## 真实语音链路

原始事件：[生产构建两轮通话](../evaluations/results/2026-10-31-living-call.json)。环境为 macOS Chrome、本机生产服务，**合成中文输入经 Web Audio 虚拟麦克风**，真实 MiniMax ASR/TTS 和已配置 DeepSeek 路由。全程没有使用物理麦克风。时间从浏览器事件测量，音频起点是实际 `AudioBufferSourceNode.start`，不只是接口返回。

| 指标 | 本次实测 |
| --- | --- |
| 点击到固定开场开始播放 | **240 ms**（本地素材；虚拟设备无需真实权限等待） |
| 第一轮说完到回复出声 | **4,202 ms** |
| 第二轮说完到回复出声 | **3,275 ms** |
| 第二轮直接开口到停止旧声音 | **362 ms** |
| 请求结果 | 2 次 ASR、2 次文本、2 次 TTS，全部 200；开场未临时合成 |
| 挂断 | 音频轨道 `ended`，AudioContext `closed`，无迟到播报 |

另外，自动化测试用安静虚拟麦克风播放仓库中的真实开场 MP3，验证无需 TTS 请求；该测试模拟能力可用性，不应冒充完整供应商测量。固定开场音频长 3.146 秒，另经真实 ASR 回转写，文字一致（标点不同）。

这次缩短的是首次拨通出声路径；后续回复仍是顺序 ASR → LLM → TTS，尚未变成流式语音。两轮样本不能称为 p95 或 SLA，不能据此断言比前版更快。物理外放回声、蓝牙、手机真机、Safari 卷线过渡和真实权限等待尚未验收。

v14 的 16 轮接口成功，中位完整响应 1.165 秒；其中一条为控制层道别。仍有模板、无依据细节和未请求的建议，见 [完整评审](../evaluations/living-companion-review.md)。有界上下文仍不等于跨天关系记忆。
