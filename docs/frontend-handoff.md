## Required usable screens
- Welcome: brand 面包, hero 今晚，先说说。, supplied subcopy. Three entry actions `start('listen')`, `start('listen',true)` (welcome text; user may then explicitly play), `start('review')`. Library affordance. Processing details accessible before first send. no forced setup.
- Conversation: clear AI and actual capabilities state (capabilities null = checking, agent.mode gives Mock vs real); meaningful activity states (never claim listening without recording). Mode controls 倾听 / 留个记号 / 复盘 / 练一题. `setMode('organize')` starts generation if context exists; other modes set goal. Textarea send and keyboard Enter, Shift+Enter newline. Can send while idle/paused/error; busy disable duplicate send. Fixed accessible 停止 and 结束 buttons (Escape stops). Messages as text, no unsafe HTML. Each assistant text has 播放 button only when tts.available. Notice and error visible as status/alert, user can retry by sending. User messages can correct matching source via sourceId (use explicit inline edit controls, no window.prompt).
- Right drawer/context panel (not an empty permanent report): sources add form with label, origin select (`user_recollection`, `source_quote`, `explicit_feedback`), text. Explicit 确认材料 and 修正 actions, revision status. Mode review should explain first add 岗位 and 一段当时的回答, JD optional, each source confirmed before analysis. 可只粘贴愿意讨论的片段. Review calls send with current input; generated content uses card/findings. For currentCard show sections, validity + revision, edit title/section text, confirm then user selects 保存到本设备 or MD / JSON export. Save preview MUST show exactly card text and selected cited excerpts, followed by explicit save click; call saveCard only then. Confirmation ≠ factual proof. `state.findings` allow rejecting inference and display quoted evidence/source revision. Stale/disputed cards cannot save/confirm/export; explain regenerate after correction. `currentCard.sections[].findingIds` determines exact findings/citations used by card.
- Practice: one editable question, 1–2 selectable dimensions, setPractice(question,criteria), then answer in composer. No invented personal answers or scores. Allow reanswer and switch question. Display derived feedback cards normally.
- End: state.lifecycle='ended'. Calm finish copy, no forced survey. If state.endSnapshot has card, readonly preview + save/export (preview applies); no sources/raw chat after ending. reset starts fresh welcome. No further model or voice calls.
- Local library modal/drawer: refreshSaved, cards preview, resumeSaved, deleteSaved with inline confirm, import JSON file input, explicit current-browser storage explanation. No localStorage. Display imported content as text. Opening a saved case for continuation creates a new session via resumeSaved.
- Voice: available ASR enables startRecording, finishRecording (stop & transcribe); cancelRecording cancels without upload. `activity='recorded'` means time limit reached and awaiting `transcribeRecorded` or discard. transcriptDraft editable; `sendTranscript` sends only after review. Show recorder time. If unavailable explain with capabilities reason and retain typing. No auto playback.
- Footer/data notice: temporary by default; no automatic save. Data processors via capabilities.processingNotice; local browser storage shared-device caveat. Display labels in product language, keep implementation details in secondary details. Mode and voice availability always accurate.

Responsive desktop/mobile, visible focus, semantic labels, good contrast, reduced motion, avoid focus traps. Small CSS motions for entrance, state bread and drawers only. All controls should work. Optional example chips may fill composer with explicitly fictional examples but should not auto-send.
