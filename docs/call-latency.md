# 电话等待时间：2026-11-02

本轮从真实线上等待拆解入手，保留 DeepSeek Flash（关闭思考）与 MiniMax `Chinese (Mandarin)_Warm_Bestie`。服务端没有保存对话或音频；所有实测均为虚构文本与合成声音。

## 发现与改动

初始公网抽样：转写 1.489 秒、模型 3.870 秒、合成 1.180 秒，三段 HTTP 合计 6.539 秒，另有浏览器停顿检测与音频解码。服务器负载接近零，主要时间花在上游模型与串行请求。

电话倾听现在使用 `/api/agent/voice`：完整模型回复通过原有结构、来源、版本和风格校验后，先把文字传回，再立即在服务端开始语音合成；音频通过同一个响应返回。浏览器不用收到文字后再发一次合成请求。这里流式传送的是“校验后的文字 → 完整 MP3”，没有提前播放未经检查的模型 token，也没有分段解码 MP3，继续兼容已有 AudioContext 播放与回声检测。

陪伴提示词合并重复要求，UTF-8 长度从 6,372 降为 3,344 字节（不等同于 token 数），保留不说教、不主动提问、尊重纠正与不编造经历的约束。倾听模式的空 findings/warnings 由控制层填写，模型仅生成回复与必要的支持标志；模型如果擅自返回分析或保存字段，仍按原规则拒绝。复盘与练习保持原协议。

## 取消与失败

- 客户端同时约束响应头和流式正文的截止时间、总大小、事件顺序、请求与来源版本。缺少结束事件视为中断。
- 挂断、切后台、自然打断会取消同一个请求及语音准备；已显示的有效文字保留，迟到音频不播放。
- 模型、TTS 分别准入、计数、去重与熔断。取消释放两段各自的租约；不会自动再付费生成或合成一次。
- 合成失败保留文字，回到明确的恢复操作。`BREAD_COMBINED_VOICE=off` 可让新页面使用原先分开的接口；旧页面继续兼容。新页面若在服务器回退后收到新接口不存在的 404/405，可退回旧接口一次；超时、5xx 或不完整响应不触发这条路径。

### 公网浏览器：说完到开始播放

固定 `tests/fixtures/voice-input.wav`，每轮新建 390×844 浏览器会话，通过真实 AudioContext / AudioWorklet 输入合成声音，再调用线上真实 ASR、模型与 TTS。以输入音频末尾到回复的 `AudioBufferSource.start()` 计时，包含停顿检测、转写、网络、生成、合成与解码，不包含扬声器硬件延迟。

| 批次 | 三轮等待 | 中位数 |
| --- | --- | --- |
| [发布前](evaluation/call-browser-before.json) | 9.475 / 10.121 / 5.794 秒 | 9.475 秒 |
| [发布后](evaluation/call-browser-after.json) | 5.108 / 10.412 / 5.094 秒 | 5.108 秒 |
| [追加分段诊断](evaluation/call-browser-profile.json) | 5.365 / 5.801 / 5.062 秒 | 5.365 秒 |

首组中位数减少约 **46%**，但最慢一轮没有改善，不能据此承诺每次都在五秒内。追加诊断中，服务端模型阶段 2.025–2.304 秒、TTS 0.731–0.952 秒；此前 10.412 秒样本的模型与合成连接耗时 8.398 秒，没有采集到该轮的独立阶段值。发布后的服务日志未记录风格修复或服务失败；因此该慢样本未发现由额外修复调用引起，不能进一步断定具体哪个供应商步骤造成了波动。

六轮都完成真实播放，没有浏览器异常，挂断后麦克风轨道均结束。初版观测脚本曾卡在等待网络收尾的 Promise，随后为该观测增加五秒上限；播放计时发生在此等待之前，不计入这个采集等待。

[自然打断实测](evaluation/call-browser-interruption.json)：模型等待中再次注入声音，约 **419 毫秒**回到倾听；旧请求被取消，下一轮真实回复成功，挂断释放麦克风。原始网络记录保留 `ERR_ABORTED`；它包含主动取消，不能把网络取消数量直接当作失败回合数。旧回复未播放，新回复播放一次。
