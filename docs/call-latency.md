# 电话等待时间：2026-11-02

本轮从真实线上等待拆解入手，保留 DeepSeek Flash（关闭思考）与 MiniMax `Chinese (Mandarin)_Warm_Bestie`。服务端没有保存对话或音频；所有实测均为虚构文本与合成声音。

## 发现与改动

初始公网抽样：转写 1.489 秒、模型 3.870 秒、合成 1.180 秒，三段 HTTP 合计 6.539 秒，另有浏览器停顿检测与音频解码。服务器负载接近零，主要时间花在上游模型与串行请求。

电话倾听现在使用 `/api/agent/voice`：完整模型回复通过原有结构、来源、版本和风格校验后，先把文字传回，再立即在服务端开始语音合成；音频通过同一个响应返回。浏览器不用收到文字后再发一次合成请求。这里流式传送的是“校验后的文字 → 完整 MP3”，没有提前播放未经检查的模型 token，也没有分段解码 MP3，继续兼容已有 AudioContext 播放与回声检测。

陪伴提示词合并重复要求，保留不说教、不主动提问、尊重纠正与不编造经历的约束。倾听模式的空 findings/warnings 由控制层填写，模型仅生成回复与必要的支持标志；模型如果擅自返回分析或保存字段，仍按原规则拒绝。复盘与练习保持原协议。

## 取消与失败

- 客户端同时约束响应头和流式正文的截止时间、总大小、事件顺序、请求与来源版本。缺少结束事件视为中断。
- 挂断、切后台、自然打断会取消同一个请求及语音准备；已显示的有效文字保留，迟到音频不播放。
- 模型、TTS 分别准入、计数、去重与熔断。取消释放两段各自的租约；不会自动再付费生成或合成一次。
- 合成失败保留文字，回到明确的恢复操作。`BREAD_COMBINED_VOICE=off` 可让新页面使用原先分开的接口；旧页面继续兼容。

## 验证记录

本地类型检查、233 项单元/集成测试、生产构建和 53 条浏览器流程通过。新增覆盖流式正文截止、缺失结束标记、错版本、候选后断流、自然打断、挂断以及语音失败保留文字。

真实发布前对照使用四条固定中文样本，按次序调用当前线上模型和语音服务。[旧版原始结果](evaluation/call-latency-before.json)中，“提交文字到音频完整返回”中位数为 4.341 秒，最慢 6.022 秒。这不包含说话时间、停顿检测、转写或设备出声，不是端到端电话延迟。

候选服务器通过真实 DeepSeek → Warm Bestie，事件顺序为 candidate/audio/done；重复请求 409，缺少会话或跨域 403。候选保留旧版 9 个静态资源，尚待正式发布后的公网复测。
