# 自然电话：延迟与输出评估

2026-10-31，北京时间。第四轮以同一台 Mac、Chrome、本机 Magpie 和原 MiniMax 配置测量。以下全部为合成情境和合成中文音源；没有上传用户真实通话，也没有把传输成功当成“情商通过”。

## 延迟

同一段 4.946 秒中文音源：“今天的面试结束了，我有一点累。先不想复盘，就想跟你说说话。”实际经过浏览器 AudioWorklet、WAV 编码、MiniMax ASR、文本模型、Warm Bestie 合成与 WebAudio 播放。计时终点是实际调用音源 start，不是文字到达。

| 指标 | 旧版 v10 / Gemini | 新版 v11 / 电话 DeepSeek |
| --- | ---: | ---: |
| 音源结束 → 第一声回复 | 11.443 秒 | 3.379 秒 |
| ASR | 0.690 秒 | 0.792 秒 |
| 文本请求 | 8.540 秒 | 1.270 秒 |
| 回复合成 | 1.164 秒 | 0.727 秒 |

匹配输入的这次测量减少约70%等待；样本很小、回复长度和上游负载不同，不是延迟保证或 p95。第二句直接打断正在播放的回复，音源开口至停止旧播放 **373 毫秒**；“等一下，我不想聊面试了。我今天买了一张很可爱的猫咪贴纸。”完整转写。第二句音源结束到新声音 **3.567 秒**，ASR1.068秒、文本1.088秒、合成0.821秒。两轮共7个真实请求全部200；播放后恢复听，安静一分钟会暂停。

生产构建更新到3210后，再做两轮真实验证：说完到回复分别4.287/3.427秒；开口到停止旧声406毫秒，7个请求再次全部200。第一轮ASR升至1.662秒，说明上游波动仍会影响总时延。本轮4次新链路观察范围3.38–4.29秒，不能据此推算长期分位数。

这里的“音源结束”包含合成文件自身的收尾静音。输入由 WebAudio MediaStreamDestination 提供，真实执行其余链路，但未验证物理扬声器/麦克风、蓝牙、移动端音频路由或真实房间回声。自动化另外测试了实际音频图内的延迟回声、高频噪声、开口与前80ms保留，供应商响应在这组回归中模拟。

## 选型与语气

8个相同单轮情境、每情境3个版本交错调用，共24次。原 Gemini v10（4096 token预算）文本请求中位数6.655秒；精简v11 Gemini（768预算）5.613秒；精简v11 DeepSeek 1.126秒，范围1.002–1.294秒。单靠缩短提示词没有解决主要等待，电话因此单独配置现有 DeepSeek 路由；文字倾听保留 Gemini，整理与复盘仍用原 DeepSeek。音色、TTS模型和语速不变，没有增加用户选择表单。

人工检查发现并修正：快模型把“一件事”塞成两件，原因未知时措辞生硬，提到旧聊天时暗示“记不起来”。提示词改成短口语、一个具体点、少问和少复述，尊重拒绝建议；不把喝水/休息换词重复，不把边界声明塞进普通闲聊；过去内容未提供时说明当前对话没有该信息。没有改模型权重，属于提示词与程序输出约束调整。

最终16轮应用接口检查全部通过JSON、长度等程序校验，中位数1.116秒、范围0.921–1.598秒；包括10个定向/留出场景和两组三轮对话。安静请求没有继续追问，拒绝生活建议时简短收回；修正核心担忧后跟随房租话题，提出猫咪贴纸后离开面试话题；记忆问题改为“这次对话里没有那条信息，上周说的公司名我看不到”。实际连续对话保留模型自己上一轮的回复，没有用预设理想回复替代历史。这些样本参与了提示词迭代，不是独立盲测。

仍不把16/16 HTTP200称为情商满分：有时会复述或追问，单件事样例给了二选一，对“拒绝肯定因为学校…”出现过语义误读，真实电话首轮也仍有泛化的“想闲扯点什么”。这些语感细节保留在记录中，后续应结合真人试听再调；不以每句硬改写或硬截断掩盖原输出。

另外测试了现有接入列表：GLM Flash本轮约6.98–8.91秒；Gemini 3.8的minimal设置没有稳定加速；Gemini3.5路由返回404；Gemini3.7三条把非JSON说明混入正文，不能作为当前可靠的快速替代。未接入列表之外的豆包，也不宣称已测试豆包。Google兼容接口的推理参数参考[官方文档](https://ai.google.dev/gemini-api/docs/openai#thinking)；Magpie及上游的实际映射不能仅凭参数名称确认。
