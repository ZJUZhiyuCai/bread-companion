# 下一轮视觉方向：先统一角色所在的世界

2026-11-02，官方 Claude Code **Opus 5.5 / high** 对用户指出的品牌栏、电话入口及当前首页／通话画面完成诊断。它读取四张截图与选定的前端文件，未运行浏览器；[完整原稿](design/opus-premium-diagnosis-original.md)区分了截图观察、代码证据与推断。此文保留当时的设计诊断；后续两轮实现与验证见 [整体视觉打磨](premium-frontend.md)。

## 主要问题

- 聊天页的电话入口常规使用 SVG 电话，首页是 Blender / Three.js 电话，同一物件的比例、材质与拨号盘不一致。
- 品牌栏的小卡通与照片质感的毛绒角色分属两套风格，字标、正文与角色台词也有多套字体。
- 纸纹、细边、渐变灯光与接触阴影没有形成同一个场景，精度较高的物件像贴在背景板上。
- 状态、字幕与次级操作需要重新分配层级，让通话主要依靠声音，仍能明确打断、静音、恢复和离开。

## 接续取舍

优先统一电话素材与光线，再收敛品牌和字体，最后处理场景连续性。照片角色、浅色基调与正常睁眼继续保留。原稿中半闭眼、自动变暗等提议与用户此前偏好不一致，不作为实施要求。

1. 让常规电话入口都来自同一 Blender 模型，静帧与 3D 保持一致；SVG 保留兼容回退用途，加载时不更换外观。
2. 品牌字标与字体收敛到两套视觉语言，优先复用自托管字体。拒信场景用于进入时的内容，不永久挂在所有页面的品牌旁。
3. 先验证浅色场景中的光向、接触阴影与手机构图，再增加素材。控制首屏资源，不把场景或 3D 下载加入语音启动的关键路径。
4. 动画只反映真实连接和播报状态。保留 44px 触控区、焦点、减少动态偏好、可见恢复路径和自然开口打断；不用假进度或固定安慰音遮盖服务等待。

这些是诊断时 Codex 对原稿的整合意见，后续实现与取舍另有记录。本轮后端发布、真实通话结果与未解决的长尾见 [语音链路记录](call-streaming.md)。
