# 面包：拟人陪伴与通话的设计参考

调研日期：2026-10-31。本轮用户最新要求优先于旧 brief：增加拟人角色、实际通话，改善语音与文字、约束输出风格，并真实测试文本模型。下列是公开资料中的产品行为与我们的设计推断，不是复刻授权或用户访谈结论。

| 一手来源 | 可核对的做法 | 面包本轮吸收的部分 |
| --- | --- | --- |
| [Pi 官网](https://hey.pi.ai/) | 倾诉、想清楚一件事、语音开聊以轻入口呈现。 | 先让人开口，工具与整理动作跟随需要出现；文字与电话同等可达。 |
| [Character Calls 官方介绍](https://blog.character.ai/introducing-character-calls/) | 一键发起双向语音；按钮打断；文字与通话切换。 | 通话自动识别一句话的结束、回复后继续听；可打断、静音、挂断；字幕留在同一段临时对话。 |
| [Character Calls FAQ](https://support.character.ai/hc/en-us/articles/23957274129691-Character-Calls-Voice-FAQ) | 通话提供文字记录，支持中文。 | 字幕始终可看，挂断后能继续打字；沿用面包的明确保存规则，不照搬其自动存档。 |
| [Replika 官方帮助](https://help.replika.com/hc/en-us/articles/360046383391-How-do-I-call-my-Replika) | 首页电话图标直接进入通话。 | 不让用户填模型、音色、题目或模式，入口应足够明显。 |
| [Replika 产品能力说明](https://help.replika.com/hc/en-us/articles/5040453297293-Can-Replika-be-my-virtual-assistant) | 把自然、支持性的交流作为核心能力。 | 角色要有可辨识的性格与温度，仍清楚说明 AI 身份，不虚构现实行动。 |
| [H2HTalk 原始论文](https://arxiv.org/abs/2507.03543) | 对话、回忆等多场景评估，指出隐含需求变化和长期记忆的挑战。 | 本轮使用虚构的多轮中文测试，检查拒绝建议、纠正误解、关系边界及上下文接续；不以一条暖心回复代替整体评价。 |

面包的实现选择：原创拟人面包角色；通话里的倾听、思考、说话、暂停由实际状态驱动。表情不宣称识别用户情绪。连续语音采用浏览器本地停顿检测、MiniMax ASR、文本模型、MiniMax TTS 顺序交接；一键打断，不声称全双工。音色固定为用户指定的 `Chinese (Mandarin)_Warm_Bestie`，不增加面向用户的配置表单。

输出目标：接住具体内容，不自动分析人格、不虚构拒因；少套话、少说教、少追问；用户说不需要建议就停止给建议；允许轻松闲聊与正向时刻。电话回复更短、适合听，不朗读 Markdown、舞台动作或长卡片。角色可以温暖、幽默，不能以排他承诺、内疚或虚构真人身份维持对话。

模型验收是本项目的小样本工程评审，包含真实输出、时延与逐例说明，不是标准化 EQ 分数、临床结论或全面模型排名。
