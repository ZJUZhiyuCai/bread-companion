## 发现与修复

| 异常条件 | 风险与处理 | 验证 |
| --- | --- | --- |
| WebGL 构造途中抛错 | Three 尚未返回 renderer 时也可能已经分配资源。现在由调用方持有原始 context，失败立即释放；初始化后失败也执行完整清理。 | 注入 framebuffer 创建异常，确认所有已创建 context 均已丢失，键盘仍能拨号。 |
| 绘制途中抛错或设备 context 丢失 | 原画面可能停住。现在退回 SVG，并停止渲染、释放几何/材质/纹理及 PMREM render target。 | 注入 draw 异常、实际调用 WEBGL_lose_context；SVG 恢复且仍能接通。 |
| 首次图形准备与接通竞争 | 软件 GPU 的冷初始化可能挤占欢迎语处理。首次通话先由 SVG 显示拨号，声音开始后才准备 3D。 | 故障后的首次通话及延迟模型测试；缓存欢迎语确实播放，不依赖模型响应。 |
| 图形故障后进入新画面 | 反复尝试同一故障图形环境可能继续占用资源。一次图形失败后本页保持 SVG；刷新可以重新尝试。 | 构造、绘制、context 丢失、损坏模型四条路径。 |
| 模型下载永不结束 | 共享下载 promise 可能永久挂起。增加包含响应体的 10 秒截止；失败允许下一画面重试。 | 持有下载直到真实截止，确认请求 abort、SVG 保持可用、下一阶段发起一次新请求。 |
| 音频引擎意外暂停/关闭 | 原先仍显示正在听且保留麦克风。监听 AudioContext 状态，发生中断立即释放采集，保留文字并提供显式重连；主动关闭前移除回调，避免误报。 | 真实浏览器先复现失败，再注入 suspend/close，确认释放麦克风、重连成功、最终所有 AudioContext 关闭。 |
| 连续点击、挂断后异步结果返回 | 重复开麦、迟到音频或模型重建画面。沿用 generation/abort/active 防线，并验证模型卸载后结果被丢弃。 | 三次点击只开麦一次、只播放一次欢迎语；挂断后释放音频和图形资源。 |
| 320px / 特大字号 | 电话文字溢出铭牌、气泡遮住右眼。给气泡预留上方空间，铭牌向左扩展，电话模型和命中区保持原位。 | 先复现失败；修复后 320/390/778/1440px 的明暗主题、标准与特大字号、无横向溢出和眼睛/标题不被遮挡检查通过。 |
| 静止、后台、减少动态 | 无意义持续绘制或残余动画。按需 RAF，后台停绘，减少动态终止招呼和落地余振。 | 记录实际 WebGL draw 次数；稳定后保持不变，挂断后活跃 context 为零。 |

## 本机结果

- `npm run typecheck`：通过。
- `BREAD_DIST_DIR=.next-calm-candidate npm run build`：通过；同一生产构建已在 3215 检查后放到本机 3210。
- `npm test`：155 项通过；音频中断修复后重新运行。
- `BREAD_E2E_PORT=3213 npm run test:e2e`：40 项通过（本机先完整 39 项，再针对窄屏/特大字号修复复验新增项及 4 项相关布局/悬停测试；发布 CI 会完整运行 40 项）。相对 0.2.1 新增 8 项 3D/通话故障、2 项音频中断/重连、3 项开场语义与布局测试。
- `npm run check:models`：通过。当前 GLB 336,668 字节、13,017 三角形、14 节点、8 个网格；无外部纹理或缓冲区。
- 实际浏览器检查：1440 桌面、320/390 手机宽度，首页、通话、暂停、继续、静音、挂断；照片伙伴未替换。

既有回归还覆盖：真实浏览器 AudioWorklet 的自然开口打断、回声与噪声抑制、保留首音、ASR 中继续讲话的拼接、取消旧模型结果、拒绝/迟到麦克风权限、后台自动暂停、文字与通话连续性、本地保存失败与导入导出。

测试使用虚拟麦克风和合成输入；浏览器音频图和缓存的 MiniMax 欢迎语为实际播放。付费 ASR/TTS/文本提供方在这些浏览器测试中被替换或阻断。这些结果不等于物理扬声器回声、真实用户语音、所有移动设备或云端当时服务质量的实测。

## 真实提供方与资产

11月1日 00:32，北京时间，在同一后端、同一语音配置的生产候选上，以合成普通话完成真实 **MiniMax ASR → DeepSeek/Magpie → MiniMax 温暖闺蜜** HTTP 链路，三个接口均 200。单次观测分别 **1,565.6 / 1,428.7 / 810.6 ms**；生成 MP3 可解码，时长 6.18 秒。随后 Claude 只改前端；这些值不包含浏览器停顿检测、网络外播放或物理麦克风，不等于用户说完到听见回复的总延迟。

输入：“今天的面试结束了，我有一点累，先不想复盘，就想跟你说说话。” 回复：“面完就先松口气，累是真的累。想聊点别的也行，我在这儿听着。” 这是合成情境的一条样本，不作情商或疗效认证。

模型源为 `scripts/3d/build_companion.py`，在 Blender 5.2.2 LTS 本机重新生成，与 DeepSeek 补丁内 GLB 逐字节一致。重建参数见 [模型指南](phone-model.md)。网页仅加载电话 GLB；数字由 Blender 内置字体转换成网格，无字体文件或第三方模型下载。Blender 的输出使用与程序自身 GPL 分开，见 [Blender 官方说明](https://www.blender.org/about/license/)。用户参考照片没有加入仓库。

当前 GLB SHA-256：`d3f1a5c4f07a9815e832651f576e0f36af7b0955bb2736fc3a75e5c710324117`。

开场验收包括：空白 Enter 留在首页；按钮可空白进入；输入法组字/Shift+Enter 不误发；长度上限生效；先听入口不申请麦克风；无 TTS 时明确只提供文字。暗色首页及对话界面通过 WCAG A/AA 严重与致命问题检查。生产依赖 `npm audit --omit=dev` 本次报告 0 项漏洞。

仍未验证：物理麦克风、扬声器回声、蓝牙、iOS/Safari 真机，以及目标用户是否感到更安抚。没有新增关系记忆或流式语音能力。

首次混合候选（音频状态修复前）的单次测量：本机 Chrome、虚拟已允许麦克风、本地缓存欢迎语、首页模型已就绪，点击到 Web Audio 开始播放为 **68 ms**。这不包含首次系统权限弹窗，也不是云端对话延迟或通用性能保证。挂断后所有测试音轨和 AudioContext 已关闭，活跃图形 context 为零。

音频状态修复后的生产构建另做了欢迎语播放中 suspend → 显式重连 → listening 中 close → 再次重连 → 挂断检查，全部通过；两次异常后所有采集音轨与 AudioContext 均已释放，最终 6 个测试 AudioContext 全部关闭。仍使用虚拟麦克风，云端请求已阻断。
