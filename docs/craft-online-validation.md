# 0.4.0 细节设计、并发和线上验收

2026-11-01。官方 Claude 负责细节设计，Codex 负责字体接入、对抗审查、后端并发与部署。本文记录实际证据，不把构建成功等同于体验质量。

## 已验证的本地结果

- 类型检查、175 项单元/集成测试、42 条 Chromium 浏览器流程、模型资产校验、无网络情境 dry-run、Next 生产构建均通过。
- Sites / Vinext 独立 Worker 构建与本地预览通过；实际浏览器完成文字回合，明确标注 Mock。线上真实链路另记，不能由它代替。
- 100 个竞争准入请求中恰好 12 个获准，其余被拒绝；实际 SQLite 执行与生产相同的 SQL 迁移和 atomic batch。复盘通道满时，电话、ASR、TTS 仍可独立准入；每访客并发上限单独生效。
- 覆盖跨实例预算逻辑、重复请求、过期租约、晚到数据库写入的取消清理、数据库缺失/故障时关闭准入、跨站/伪造 cookie、转发 Host、重叠请求的配置隔离、慢请求体占位、单探测熔断与旧成功不能误清故障。
- 固定开场准备与麦克风许可并联；拒绝权限、挂断、迟到许可、准备失败不触发付费合成，也不迟到播放。能力请求与本地存档读取并行。
- 现有浏览器回归覆盖真 AudioContext 与合成输入：自然打断、保留开头、旧模型/ASR 结果取消、静音、后台暂停、音频引擎关闭恢复、WebGL 故障降级、卡片保存/撤销及存储失败。

## 真实服务与线上验证

[在线体验](https://bread-companion-czy.rosscai.chatgpt.site) 已由 Sites 原生发布成功，公开访问不需要维护者电脑开机。真实提供方为万界方舟 DeepSeek Flash 与 MiniMax Warm Bestie，secret 仅存服务端环境。

第一次生产测试揭示了本机 Node 测试未发现的两个 Worker 兼容问题：`redirect: error` 不受支持，类成员方式调用原生 `fetch` 触发 incorrect-this。已改为手动拒绝重定向和无接收者调用，并用两个回归测试确认不会向重定向地址转发密钥、文字或音频。第二次真实链路通过，失败记录未冒充成功。

2026-11-01 03:01（北京时间），单个合成中文音频回合：

| 阶段 | HTTP | 客户端完整请求 | 供应商处理段 |
| --- | --- | --- | --- |
| MiniMax ASR | 200 | 3,597 ms | 2,572 ms |
| DeepSeek 电话回复 | 200 | 2,415 ms | 2,063 ms |
| MiniMax TTS | 200 | 1,873 ms | 1,169 ms |

三段完整请求合计约 7.89 秒；这不是浏览器说完至首响的测量，ASR 前的停顿判定与播放器准备另计。公网样本比之前本机更慢，不能把本机 1.06 秒文本样本当成线上保证。音频为可解码 32 kHz 单声道 MP3，4.09 秒，67,956 字节。[原始合成情境记录](craft-online-smoke.json) 保留输入、回复、时间和音频哈希，不含 cookie 或密钥。

缺少访客 cookie、错误 Origin、缺失 Origin 均 403；畸形输入 400；同一模型请求切换通道重复提交为 409，没有再次调用供应商。实际生产 D1 表结构只含六个元数据字段；检查时 6 条请求记录的活动租约全部为 0。真实手机尺寸浏览器中，原地重试后只出现一次用户消息和一次回复，输入与结束按钮仍可操作。网页点击“念给我听”后进入播报状态并正常恢复，没有浏览器错误；结束会话能回到首页。

复现需明确选择合成音频与 `--live`，会产生服务费用，不自动重试：

```sh
node scripts/smoke-online.mjs --live --origin https://your-site.example --audio /absolute/synthetic.wav --output .local/online-smoke
```

根 Next 与 Worker 都已配置安全响应头，Worker 直接在返回边界施加，避免依赖框架适配差异。字体在 Next/标准 Worker 资产配置中使用内容哈希缓存；当前 Sites 静态分发仍返回 `max-age=0, must-revalidate`，该平台缓存策略尚未改成 immutable。字体可正常加载，不能将其描述为已验证的一年缓存。

## 限制

语音仍是 ASR → 文本 → TTS 顺序；并联没有通过重复付费请求竞争速度。物理麦克风、外放回声、蓝牙、真实 iPhone Safari / Android 和低端机长时间帧率尚未验证。匿名共享配额限制调用数量，不是完整反机器人服务；全站 1,200 次滚动请求预算也不是无限在线承诺。全文质量、长时记忆与跨天关系连续性仍见路线图。

最终在线版本为 Sites version 5（源码 `fbd3465d258405ee846f760ae2623e77dfc89043`）；原生发布状态 succeeded，环境 revision 1。发布后实际 HTML 响应确认 `nosniff`、`no-referrer`、仅自身 microphone 权限与禁止框架嵌入。189 个发布应用文件与本仓库对应文件逐一 SHA-256 相同。

## 最终 CI 捕获的开场冷加载问题

PR #8 的一次后续 CI 中 41/42 浏览器用例通过，SVG 键盘拨号用例进入错误态。网络 trace 显示欢迎音频 HTTP 200，但应用走了云端合成回退；该测试禁止云端调用，因此揭示了不必要的付费回退。进一步的受控测试显示，网络面板上的请求时长不足以表示浏览器将首个音频交给应用的时间；延长读取限时、去掉纹理或调整缓存策略都没有稳定解决复现，因此没有把这些尝试当作修复。

最终将 52,980 字节的固定合成开场随应用代码加载，匹配默认音色时直接解码播放，不再单独下载开场文件。它不包含用户对话；其他音色仍由已配置服务合成。`scripts/embed-call-greeting.mjs --write` 可从公开原始录音重建，新增单测逐字节核对一致性。拒绝权限、挂断和迟到许可仍不能播放或计费。

SVG 键盘用例明确让独立音频文件和云端合成都不可用，仍必须播放一次真实录音、保持零 WebGL 并正常挂断；没有删除断言或启用自动重试。原有拨号取消用例改为等待真实虚拟麦克风的许可，验证取消后不迟到播放。完整单测现在为 175 项，浏览器流程仍为 42 条。

本机 Chromium 与静音虚拟麦克风的针对复测中，点击到固定录音实际开始约 401 ms，录音 3.146 秒，没有合成或转写请求；这不是物理麦克风或公网回复延迟。[测量记录](craft-opening-browser.json)。
