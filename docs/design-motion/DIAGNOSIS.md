# 面包 · 动效与延迟诊断（基线 3e4ad81）

> Claude Opus 5.5，2026-11-04。只读了本目录的源码与 `docs/assets/premium` 三张上一轮截图，没有运行浏览器、没有测帧率。下面的“现象”是从代码推出来的，凡是标了 **[实测]** 的，需要 Codex 在真实页面上确认或量化。

## 0. 一句话

上一轮把“布景”做对了，这一轮的问题都在**时间**上：谁先到、谁在一直动、一个状态怎样交给下一个状态。现在的面包在静止时也在每帧重画；等待回复的那一秒里，光会先暗一下；从首页走进对话，面包会消失，再在角落里换成另一只面包，而且一进来就连跳两下。

## 1. 进场：先到的应该是面包

### D1 面包本体是首屏最后到的大图
- `bread-plush.webp` 只出现在内联 SVG 的 `<image href>` 里（`BreadBuddy.tsx:284`，遮罩里还有一次 `:255`）。浏览器的预加载扫描器不解析 SVG `<image>`，要等 HTML 解析到那里才开始请求，而且优先级是默认的。
- 同一屏里，电话静帧在 `layout.tsx:30` 被 preload，`Companion.tsx:143` 的海报还带着 `fetchPriority="high"`；字体也 preload。
- 结果大概率是：**文字 → 电话 → 面包身体**。电话比主角先到。上一轮修掉了电话的“三次突变”，但面包这边的顺序没被处理。**[实测：首屏瀑布图与 LCP 元素]**

### D2 五官比身体先到
- 眼睛、睫毛、腮红、小花、缝线嘴是矢量层（`BreadBuddy.tsx:294-315`），HTML 一到就画出来；身体照片还在路上时，墙上先浮着两颗玻璃眼珠和两团粉色。顶栏的头像 `BreadMark`（`BreadBuddy.tsx:829`）在奶油色圆盘上也会先出现一双眼睛。慢网和首次访问时最明显。
- 地面接触阴影 `.p-ground` 同理，会先在地上出现一块没有主人的影子。

### D3 “我是面包”这句字幕不等面包
- `.hello-bubble` 固定在 0.4s 后淡入（`globals.css:2400`），和面包是否已经在画面上无关。面包晚到时，会先出现一句“我是面包”，说话的人却还不在。

## 2. 一直在动的东西：丝滑的前提是主线程空着

### D4 呼吸每帧重画整只面包
- `.p-breathe { animation: breathe 5.2s infinite }`（`globals.css:1135`）作用在 SVG 内部的 `<g>` 上。SVG 内部的 transform 不进合成层，每一帧都要重新记录、重新栅格化整只面包，包括三张以照片 alpha 为蒙版的补光层（`p-light--key/shade/bounce`）。
- 首页、聊天侧栏、手机顶条、通话页都常驻。换句话说，**页面静止时主线程也一直在画**。它和收音电平、音频解码、React 更新抢同一条线程。**[实测：Performance 面板里 Paint 是否每帧出现]**

### D5 两个固定节奏的“表演循环”，而且切换时会跳
- 用户说话时的点头 `nod 1.6s infinite`（`:1293`）和思考时的 `ponder 3.6s infinite`（`:1302`）同样是 SVG 内重画。
- 它们不来自任何真实信号，是按节拍播放的“我在听”“我在想”。
- 更具体的问题是跳变：`ponder` 的 0% 关键帧是 `rotate(-2deg)`，一进入思考，面包就以脚为轴瞬间歪 2°，头部位移约 9–11px。离开思考时，无限动画被移除，又从中间值弹回原位。每一轮对话至少两次。这正是过去“快速抖动不亲近”的同一类问题。

### D6 说话时嘴每帧改两条 path
- `useMouth` 在说话期间是 60fps 的 rAF（`BreadBuddy.tsx:739-751`）。每帧都在改 `d` 属性，带着整只面包重画。缝线嘴在屏幕上只有十几到二十几像素宽，60fps 和 30fps 看不出差别。

### D7 收听电平在 SVG 里驱动两处过渡
- `.p-pose` 的 `translateY(var(--lvl)*16px)`（`:1285`）和瞳孔 `--pupil: calc(1.16 + var(--lvl)*0.08)`（`:1289`）都随电平变化，各带 0.18s / 0.7s 过渡。用户说话期间，SVG 几乎不停重画。电平真正有意义的表达已经有了，就是墙上的光（`.cstage__light`，HTML 层、合成）。

### D8 电平每跳一次，整棵通话画面都重渲染
- `CallStage` 每次拿到新的 `call` 和 `level`，都会重渲染 `PlushSvg` 和 `PhoneFigure`。前者 `lookAt={[0.8, 0.6]}` 每次都是新数组，后者是上百个节点的矢量电话。上游 `vm.call.level` 的更新会让 `BreadApp` 整树都走一遍，频率由 hook 决定。**[实测：通话收听时 React Profiler 的提交频率；不在我修改范围，但前端这边可以先把重的子树隔开]**

### D9 两处“看不见的”大面积模糊
- 顶栏 `backdrop-filter: blur(12px)`（`:2742`）。顶栏是网格的一行，下面没有滚动内容，只有 `.session::before` 的平滑渐变，模糊前后看起来一样。但生成时这层渐变在做 `glow-breathe`，于是每一帧都要重算一次整条顶栏的模糊。
- 对话框 `::backdrop` 的 `blur(5px)`（`:2076`）盖住还在呼吸的面包时，同样每帧全屏模糊。

### D10 打开通话文字记录时，舞台宽度过渡会逐帧重建 3D 缓冲
- `.callroom__stage { transition: width 0.35s }`（`:5363`）每帧改布局 → 3D 画布的 ResizeObserver 每帧 `setSize` 加 `render`，也就是约 20 次 WebGL 缓冲重建。上一轮的“缩放即重画”修复让它不会闪空，但代价是这 0.35 秒里 GPU 和主线程都很忙。

### D11 “语音通话”前面的小绿点用 box-shadow 做脉冲
- `live-pulse` 动画的是 `box-shadow`（`:6873`），每帧重绘。面积小，但整场通话都在跑，而且换成 transform/opacity 不需要任何代价。

## 3. 通话里的“等”：感知延迟主要发生在这里

### D12 说完的那一刻，光先暗一下
- 收听时墙上的光是 `0.62 + 电平×0.38`。进入转写/思考后改用 `light-breath`，它的 0% 关键帧是 `opacity 0.46 / scale 0.98`（`:6897`）。CSS 动画从第 0 帧开始，不会从当前值过渡，所以用户一停口，**光立刻往下掉一截，再慢慢吸气**。
- 这是延迟期里的第一个画面。它读起来像“断了一下”，而且每一轮都发生。

### D13 缺少一次“收到”
- 从“嗯，在听”到“嗯，让我想想”，标题瞬间换字，面包从点头循环直接跳进 ponder，没有一个单次的、和真实相位变化一一对应的“嗯，收到了”。人在电话里感知等待，是从对方最后一次回应开始算的。这里一个短小、如实的确认，比任何加载动画都更能缩短主观等待。

### D14 所有文字都是瞬间替换
- 相位标题（`CallRoom.tsx:150`）、主键图标（说完了 / 插话 / 打开麦克风 / 继续 / 再试）都是瞬间换。字幕方面，新一句和上一句复用同一个 `<p>`，不会像电影字幕那样“换一行”。被打断时那一句的变淡（`.is-cut`）也是瞬间的，`.cap--bread` 上写的 `transition: opacity` 作用不到真正变化的 `.cap__text`。

### D15 进入通话是硬切，光一开始就是全亮
- 从首页点电话，通话间直接出现。墙上的光直接以目标亮度出现，没有“灯亮起来”的过程。

## 4. 文字对话

### D16 “在想”到回复的交接会闪
- 占位行 `msg--thinking` 被移除，回复行整行从透明淡入（`.msg { animation: msg-in }`，`:3049`），左边的小头像在同一位置**消失再淡入**，闪一下。
- 回复快的时候（规则演示、短句），“在想”会出现不到 0.2 秒就被替换，读起来是一次闪烁，而不是一次等待。

### D17 面包的回复和你的便签用同一种出现方式
- 回复是整段一次到达（核对过才给），出现时和你自己发出的便签一样，都是“往上浮 10px”。面包的话是它自己的笔迹（Bread Voice），出现方式却没有“写下来”的感觉。

### D18 朗读高亮瞬间出现、瞬间消失
- `.msg.is-speaking` 的荧光笔下划线（`:3167`）没有过渡。

## 5. 页面之间：同一个面包

### D19 首页 → 对话、对话 → 晚安、晚安 → 首页都是硬切
- 首页右边的大面包消失，左上角的小面包出现；电话也一样。两者在身份上是同一个角色，画面却在说“换了一只”。
- 进入对话后，`wave` 立刻 `hop 0.9s × 2`，以 64 单位的幅度连跳两次（`:1266`），这就是“快速弹跳”。安抚感要求的恰恰相反：先落座，再打招呼。

## 6. 不在我范围、或必须实测才能定的

| 项 | 为什么 | 建议 |
|---|---|---|
| `vm.call.level` 的更新频率 | 决定通话时整树重渲染的次数 | Codex 用 Profiler 看提交频率；前端已把面包与电话子树隔开（见实现说明） |
| `.conversation` 的 `mask-image` | 带蒙版的滚动容器在部分 Android Chrome 上可能退回主线程滚动 | **[实测]** 低端机滚动；如果掉帧，就改成在容器上下各盖一条与墙同色的渐变 |

## 7. 这一轮的设计原则

1. **面包整只到达。** 五官、腮红、小花、影子与身体同时出现。主角先到，电话随后，“我是面包”在面包出现之后才开口。
2. **只留一个常驻循环：呼吸，并且放在合成层。** 其余动作都由真实状态触发，是单次、可中断、不会回弹的姿势变化。去掉按节拍表演的点头和摇摆，改由真实的声音电平和一次性的“收到”来表达。
3. **等待里的光是连续的。** 收听结束时光不掉；“想”的呼吸从当前亮度长出来，结束时淡回去，而不是被剪断。
4. **同一个面包在页面之间移动。** 首页的面包和电话滑进对话的角落；结束时滑进晚安的灯下。只用于不涉及麦克风、声音和手机键盘的那几步。
5. **任何新过渡都不排在按钮、收音、输入、打断或挂断前面。** 通话、挂断和“先听一小段”保持直接切换；动画只作用于已经可用的元素本身。
