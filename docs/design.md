# 面包 · 第二轮前端与交互设计

> 2026-10-31 · Claude（前端）· 后端/全流程测试：Codex
> 这一轮依据用户原话：“前端太粗糙了，需要用户配置的地方太多了，应该把复杂留给 agent，把温暖留给用户。”
> 设计不受 product-brief 里固定流程/界面规定约束；产品边界（不伪造、不越权、默认临时、显式保存、停止/结束）照旧。

## 1. 一句话方向：灯下的一张小桌子

收到拒信的那个晚上，人不想“打开一个工具”，想找个地方坐下。
面包的界面就是**深夜面包房里一盏还亮着的灯，和灯下的一张小桌子**：

- 灯是唯一的“大视觉”。首屏的灯照在“今晚，先说说。”上；面包在想事情时，灯光像面团发酵一样慢慢起伏；结束时灯熄了，面包睡着。
- 桌子上只放用户自己的东西：说过的话、放进来的材料、留下的小签。分析、证据、版本这些“复杂”都在桌子底下，由 agent 和控制器处理，用户想看时才翻出来。
- 面包是一个小小的角色，**坐在输入框的边上**，不是一个占屏的头像，也不是状态面板。它的表情和旁边一行字说明它此刻在做什么（在想 / 在录这一段 / 在念给你听 / 停下了），不只靠颜色。

## 2. 这一轮删掉了什么（把复杂留给 agent）

| 上一轮 | 这一轮 |
| --- | --- |
| 顶部四个模式标签：倾听 / 留个记号 / 复盘 / 练一题，用户先选模式再说话 | **没有模式开关**。默认就是聊；`send()` 自己识别“帮我复盘一下”这类明确请求。模式只作为内在状态，必要时以一行“正在做什么”出现，并带一个“回到只是聊聊”。 |
| 复盘要先放材料、选来源类别、起名、点核对、再点“开始复盘” | 一个按钮“看看那段回答” → `vm.assist('review')`。缺上下文时 agent 只在对话里问**一个**问题。 |
| 练习要先填题目、勾 1–2 个维度才能开始 | “练一题” → `vm.assist('practice')`，agent 从聊天和材料里选题、定关注点并直接在对话里问出来。题签上有“换一题 / 调一调 / 不练了”，调一调才出现可选表单。 |
| 放材料：选三种来源类别 + 起名 + 内容 + 再点“确认归属” | 一个框，粘贴，“放进来” → `vm.addMaterial(text)`。在输入框里粘贴长文时，面包会轻声问一句“这段像是材料，要放进来吗？”，不自动做任何事。 |
| 卡片：改字 → 确认这一版 → 另点保存 → 预览 → 保存，四步 | 卡片出现在对话里，像一张面包签。“留下这张…” 打开预览，“就留下这些” → `vm.saveCard()`，一次明确动作。改字/删栏仍然可以；引用折叠在“依据”里，展开就能看。 |
| 顶栏常驻：AI 角色说明 + 服务状态 pill + 当前状态 + 当前模式 + 材料 + 档案 + 停止 + 结束 | 顶栏只剩：“面包”字标 + 一枚小小的「AI · 演示/真实」章（点开是“关于面包”）、卡片与材料、以前留下的、停止、结束。 |
| 入口页三张大卡片 + 一个输入框 + 三颗服务状态芯片 + 两段说明 | 灯 + 标题 + 一张“写下第一句”的便签 + 三条轻轻的“别的方式”。服务、数据、字号都收进“关于面包”。 |

## 3. 把温暖留给用户：几个具体的瞬间

1. **第一句话就是入口**。首屏的输入框是一张便签，写了按“说给面包”就开始；不写也可以点“我想说几句”。
2. **面包说话像写信，你说话像递纸条**。面包的回复用宋体、无气泡、留白大；用户的话在牛皮纸便签上。读起来像两个人在桌边说话，而不是客服窗口。
3. **在想，不是在打字**。没有假装流式的打字动画（产品规定也不允许）。面包“在发酵”：轻轻起伏，旁边写“在想，想好、核对过才会一起给你”。
4. **小事是邀请，不是模式**。当用户已经说过话，输入框上方出现一行：“想的话也可以 · 留个记号 · 看看那段回答 · 练一题”。初次倾诉时不出现，也绝不自动进入分析。
5. **面包签**。记号卡是牛皮纸吊牌（有穿绳的孔），复盘卡是烘焙小票（锯齿边）。草稿是虚线边、写着“草稿 · 可以改”；需要重新整理的会“褪色”，并直接给出“让面包重新整理”。
6. **留下 = 装进纸袋带走**。保存预览只说三件事：会留下什么、留在哪里（这台设备的这个浏览器）、不会带走什么。只在 `savedCases` 真的出现这张卡片后才说“留好了”。
7. **熄灯**。结束页的灯缓缓熄灭（减弱动效时直接是熄灭状态），“今晚先停在这里。”没有问卷，没有下一步任务。
8. **以前留下的**。像打开一个小抽屉，每张都是一个签；打开后是三个选择：“继续看这道题 / 今天聊别的 / 暂时不看”，没有提醒，没有催促。

## 4. 信息架构

```
入口（灯下）
 ├─ 写下第一句 → 会话（listen）并发送
 ├─ 我想说几句 → 会话（listen），光标在输入框
 ├─ 现在不想说，先听一小段 → 会话（listen, welcome），文字先到，播放需点击
 ├─ 我想直接复盘 → 会话（review）+ assist('review')，agent 在对话里问一个问题
 ├─ 以前留下的（对话框）
 └─ 关于面包（对话框：AI 身份、服务、语音、数据、字号、键盘）

会话
 ├─ 顶栏：面包 [AI·演示] ｜ 卡片与材料 ｜ 以前留下的 ｜ 停止 ｜ 结束
 ├─ 对话（log）：开场一行身份说明 → 消息 → 在想… → 面包签（当前卡片）
 ├─ 底部 dock（始终可见）
 │   ├─ “正在做什么”条（复盘/整理时一行；练习时是题签）
 │   ├─ 小事邀请（留个记号 / 看看那段回答 / 练一题）
 │   └─ 输入框（面包坐在边上）：材料、录音、发送；录音中/转写草稿时变形
 └─ 桌上（桌面右侧抽屉 / 手机底部抽屉）：卡片 → 面包看到的 → 你放进来的材料

结束（熄灯）
 ├─ 有快照：只读面包签 + 留下这张… + 导出
 ├─ 无快照：“这次没有要留下的东西，这也是好好结束。”
 └─ 再开一次 / 以前留下的
```

## 5. 视觉语言

- **两种夜晚**：浅色是“暖灯下的纸”（#F6F1E7 纸色、#23262B 墨色），深色是“夜里的面包房”（#14161D 夜色、#F1EADF 奶油字）。随系统 `prefers-color-scheme`，两套都调过对比度。灯光是唯一的渐变，且很淡。
- **字体**：面包的话和标题用系统宋体（Songti SC / Noto Serif SC），界面和用户的话用系统黑体。不加载任何外部字体或资源。
- **颜色只做提示**：珊瑚色只用于“正在录音”和删除确认；靛蓝是链接与焦点；面包皮的棕色是面包本身和卡片。所有状态都有文字。
- **形状**：大圆角的纸、牛皮纸、虚线草稿边、锯齿小票边、穿绳孔。阴影很轻，像纸放在桌上。
- **动效**：发酵起伏（生成中）、蒸汽（念给你听）、录音点的呼吸、卡片“落到桌上”、熄灯。`prefers-reduced-motion` 下全部关闭或变为瞬时。

## 6. 交互细节与边界（照旧要守的）

- **语音半双工**：麦克风只在用户点击后请求；录音中输入框变成“录这一段”的条：计时、上限、“说完了”和“不要这段”。转写结果先进可编辑草稿，用户改完点“发出去”。播放只在点“听”之后；正在念时那条消息显示“停”。ASR/TTS 不可用时按钮说明原因、文字照常可用。
- **停止 / 结束**：顶栏常驻“停止”（有事在进行时变醒目）和“结束”；`Esc` = 停止（对话框打开时 Esc 只关对话框）。结束立即调用 `vm.end()`，不加确认弹窗。
- **保存只在本浏览器、只在用户点“就留下这些”之后**；成功以 `savedCases` 中出现该卡片为准（或保存后新出现的“已保存”提示），否则如实显示“没有收到保存成功的回执”，并提供再试一次与导出。预览打开后卡片若变了，不保存没看过的版本，提供“看最新这版”。
- **来源纠正与引用**：材料在“桌上 → 你放进来的材料”，每段都可“改一改”（会成为新版本，依赖它的内容标为需要重新整理）。卡片和发现里的引文逐字显示，点来源名会跳到对应材料并高亮。
- **“我不这么看”**：发现条目可以标为有异议（二次确认），依赖它的卡片随之需要重新整理。
- **AI 身份**：对话开头一行“面包是 AI，不是真人，也没有人在后台看着”；顶栏小章随时可点开“关于面包”。演示模式在小章、卡片上都写“演示”。不声称真人值守；拒因未知就写未知。
- **支持指引**：`supportState === 'support_guidance'` 时，对话顶部出现一张安静的卡，建议联系信任的人/当地紧急服务，并说明面包不会替你联系任何人。
- **无障碍**：对话是 `role="log"`；状态变化走 polite live region；所有图标按钮有文字标签；对话框用原生 `<dialog>`；滚动区可聚焦；触屏下点击区域 ≥ 44px；字号三档（关于面包里调，只在本页有效）。

## 7. 需要后端（Codex）协助 / 确认的点

1. `BreadViewModel` 类型请加入 `assist(mode)` 与 `addMaterial(text)`；前端用 `components/vm.ts` 里的 `BreadVM` 交叉类型调用，加入后两边一致。
2. `saveCard()` 失败时请设置 `error`，成功时请让 `savedCases` 含有该 `caseId` 与该卡片（前端据此判定成功）；保存前若会把草稿确认成新 revision，请保证预览里那一版仍是被保存的内容。
3. 结束时若当前卡片是**未保存的有效草稿**，希望也能进入 `EndSnapshot`（只读、可在结束页“留下这张”）——否则用户在合并保存流程下没有机会在结束页保存。若产品上不允许，结束页会如实显示“没有要留下的东西”。
4. `exportCard()` 是否允许导出未确认草稿：前端只在卡片已确认/已保存/结束快照时显示导出。
5. “以前留下的”里的单份档案导出由前端在本地生成（`components/exporters.ts`，JSON 即原样 `SavedCase`）。请确认与 `importSaved` 的格式兼容，或提供 `exportSaved(caseId)` 以便替换。
6. `vm.setPractice(question, criteria)` 在“调一调”和“练这道”里被调用；criteria 可能为空数组（让 agent 决定关注点），请确认允许。
7. 消息上的 `sourceId`（用户的话被记为材料时）会显示“已放进材料 · 看看”；`addMaterial` 产生的来源希望 `label` 为简短可读名（如“粘贴的材料 1”）。

## Codex 接入说明（与 Claude 原稿分开）

后端已补齐 assist、单框材料提交、agent 自动选题与关注点、草稿的显式保存/导出、结束时的有效最小草稿快照，以及只改题目时的默认关注点。恢复存档只带入有效原话摘录，不恢复旧聊天，也不重复确认同一份已保存文字。addMaterial 最终返回 boolean，供界面在失败时保留输入。

保存回执、确认状态变化、重复错误、失败后的输入保留、模态停止控制和安全 Markdown 导出由 Codex 做了必要接入修正，具体见 acceptance.md；视觉创意保持 Claude 原稿。
