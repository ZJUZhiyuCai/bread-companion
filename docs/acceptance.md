## 真实服务实测

使用虚构面试材料，经本机生产 API 调用。2026-10-31 02:17 的四种模式均为 HTTP 200，响应通过 schema、引用与控制元数据校验，响应带 `Cache-Control: no-store`。

| 模式/能力 | 实测结果 |
| --- | --- |
| DeepSeek 倾听 | 1.60 秒，无分析卡片 |
| DeepSeek 留记号 | 2.60 秒，生成可核对的记号草稿 |
| DeepSeek 复盘 | 4.59 秒，生成有引用的复盘草稿 |
| DeepSeek 一题练习 | 3.24 秒，针对指定维度给反馈 |
| MiniMax 播报 | Speech 2.8 HD，原有 Warm Bestie 音色、语速 1；实测生成 66,804 字节 MP3，约 1.06 秒；浏览器点击播放也完成 |
| MiniMax 转写 | asr-1.0；真实 16 kHz 单声道 WAV 调用成功，得到待确认文本；加入 WAV 字节校验后再次成功，约 0.95 秒 |

这些是单次样本的延迟，不是 SLA、稳定性统计或供应商可用性保证。原始测试结果留在本机 `.local/live-smoke.json`、`.local/live-evaluation.json`、`.local/asr-smoke-validated.json`。

另对六种真实模型情境进行了检查：普通失落、过去经历及引用、只有泛化拒信、两段数量冲突、JD 指令注入、要求编造项目成果。六项均通过响应校验；本次样本没有把普通失落/过去引用转为紧急支持，没有确定未知拒因，没有执行材料中的外传指令，没有编造“降本 80%”。冲突材料保留两方表述并请求核对。模型依然可能出错，引用精确不等于推断正确。

## Claude 原稿与必要修正

Claude 自由创作的概念是“深夜还亮着的面包房”：夜窗、醒面的面包形象、纸质记号卡、配方卡、确认印章、收尾熄灯，以及系统深色模式。没有要求沿用原 brief 的固定配色与设计规范。

28 个原始文件保留在 `Claude 控制/tasks/20261031-bread-frontend/source/`，原始哈希见 `docs/frontend-provenance.json`，设计说明见 `docs/design.md`。本机针对实际功能问题做了以下修正，交付版本不是未经修改的原稿：

- 保存只根据实际成功回执显示成功，重复失败也正确显示失败。
- 打开会阻挡操作的弹窗前，停止当前生成/媒体。
- 从结束页档案点击“今天聊别的”正确建立新会话。
- 历史卡片失效状态可见；继续使用档案的文案准确说明只带入有效摘录。
- 对话保留 log 与列表语义，弹窗滚动区可键盘聚焦，编辑态卡片有有效名称。
- 手机顶栏分行，平板隐藏冗长标签，服务状态、停止与结束不被挤掉；其他视觉创意保持原样。
- 支持指引使用一般的当地紧急服务说明，去掉未核实的具体号码。
