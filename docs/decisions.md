# 实现决定 · 2026-10-31

- 用户指定前端通过“Claude 控制”项目由 Claude 设计，后端由 Codex 实现；用户随后明确要求给予 Claude 创意自由。原配色与布局仅作参考，没有作为设计约束。
- 首轮从空目录新建 Next.js App Router / TypeScript 项目，CSS 与组件由 Claude 设计。先验证 Mock 的数据与取消规则，再接入已有真实服务，不设置额外阶段批准。
- 首轮文本使用本机 Magpie 的 `wanjie/deepseek-v4.1-flash-1017`，通过 Anthropic 兼容接口调用；协议也支持 OpenAI Chat Completions。服务端统一生成控制元数据，模型只返回内容。
- MiniMax 沿用“Claude 控制”项目已核验的 Speech 2.8 HD / `Chinese (Mandarin)_Warm_Bestie`，语速 1。转写使用 MiniMax asr-1.0。所有凭据仅进入本机 `.env.local`，不传 Claude，不进源码与浏览器。
- 引文采用带来源修订号的稳定片段 ID，按 Unicode 码点分段，不使用坐标。引文逐字验证。普通字符串长度上限按 JavaScript UTF-16 code units 计数。
- 模型上下文最多 6 个 500 码点片段，最近 16 条消息且历史不超过 12 KiB，模型数据体不超过 36 KiB。字节限额是保守输入边界，不冒充精确 token 统计；输出最多 4,096 tokens。单次任务最多一次结构修复，不自动重试超时或不明确的供应商失败。
- 对模型漏写的空引用数组规范为空数组，事实与推断仍必须有有效引用。卡片只取 type/title/sections，忽略模型附加的卡片元数据；顶层越权字段被拒绝。服务端自己赋 ID、版本、状态和时间，模型永远不能确认或保存。
- 默认仅当前页内存，IndexedDB 只在用户保存/导入后写入。卡片文本删空时同时去掉该栏引用关系，保存预览与实际摘录一致。来源修正也会把本机旧存档中相关内容标记失效。
- 录音由 MediaRecorder 采集，浏览器本地转为 16 kHz 单声道 PCM WAV，再发 MiniMax；解决服务未明确支持 WebM 的格式差异。服务端再次核验真实 WAV 字节、时长和大小。
- 服务端只接受 localhost/127.0.0.1，校验 Origin 和 Fetch Metadata，关闭跨域，绑定回环地址。每类服务最多 3 个并发、30 次/分钟、240 次/小时；这是本机费用保护，不是公开服务的认证系统。
- 不提供公共部署、账号、云同步、推送、耳机物理按键或全双工录音。本轮无需数据库服务或复杂多 Agent 框架。


## 交互打磨第二轮

- 用户最新要求“把复杂留给 agent，把温暖留给用户”，优先于原 brief 的固定配置流程。官方 Claude Opus 5.5 / high 在独立阶段 `20261031-bread-refinement` 重做前端；Codex 负责便捷接口、真实服务联调与全流程测试。
- `assist` 支持一键整理、复盘、练习。练习准备由真实模型选一道题和默认关注点，返回结构化 `practiceSetup`；准备阶段不允许评价尚未发生的回答。控制器验证结果后安装题目，仍拒绝迟到回包和模型越权。
- 常见明确的自然语言请求可以切换工作方式，拒绝分析优先，引用/不确定表达不会作为复盘同意。未识别的表达仍作为当前对话处理；这不是任意语义都能准确识别的分类器。
- 粘贴材料自动命名，采用“用户提供/回忆”的保守来源归属。用户提交修正即采用新版本，旧判断仍失效，无须再点核对。恢复已存档原文不重复配置。
- 显式保存预览将表述确认与保存合并；结束保留已展示有效草稿的最小只读快照，原聊天和完整来源清除。草稿不会自动持久化，结束后也可明确保存/导出；无卡片时不凭空生成总结。

## 拟人伙伴与电话第三轮

- 官方 Claude 任务 `20261031-bread-companion-call` 负责原创角色与前端。参考 Pi 的低负担入口、Character Calls 的单键接通/插话及文字连续性、Replika 的首页通话入口，未复制这些产品的角色或资产。原稿和本机正确性修正分开溯源。
- 后端新增独立 CallController 与 BrowserCallAudio。通话生命周期和每轮请求都有失效标识，取消向 API/供应商传递，同时从客户端丢弃迟到结果。单段录音原流程继续使用 MediaRecorder；通话用 AudioWorklet 和本地能量门限切句，最大 55 秒、默认停顿 1.3 秒。
- 通话主动开启自动发送；不额外要求每句点确认。原始录音不存档，识别结果加入当前文字会话。挂断只结束通话，结束才结束整个会话。页面隐藏或一分钟安静时暂停并释放设备，不在后台持续听。
- 现有 Magpie 没有豆包模型。对已可用的 DeepSeek、Gemini、MiniMax、GLM 做合成情境探测后，倾听采用 Gemini，证据整理仍用 DeepSeek。配置只在服务端，普通用户没有模型选择表单；模型名称是现有路由标识，服务商具体底层版本未独立审计。
- 提示词当前为 `bread-2026-10-31-v10-call`：尊重不建议/不追问、接纳纠正、少套话、身份诚实、不承诺排他或永久陪伴、不编造记忆或感知。隐私回答要区分本地保存与供应商保留。程序检查文字长度、问题数量、格式及少数明确过度承诺，最多修复一次，失败不直接展示。它不是完整的情商或安全判定器。
- 电话回应通常 20—65 字，上限 100 Unicode 码点；普通倾听文字上限 180，其他文字 240，紧急支持回复单独允许 240。详细复盘仍在卡片中，不朗读整张卡。
- Gemini 在本轮情境中比较贴合对话，但比 DeepSeek 慢。当前选择优先对话表现，不静默切回更快模型；费用、网络、服务不可用时显示真实错误，不自动无界重试。
