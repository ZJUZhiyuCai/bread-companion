# 0.2 对话复测：改善与剩余问题

2026-10-31。仍使用 `companion-zh-v1` 的 8 个虚构情境、16 轮；不是新的留出集。Codex 知道模型身份且每轮只采一次，以下为可核对的质性评审，不是盲评或标准化 EQ。

原始输出全部保留：[v12 基线](results/2026-10-31-bread.json)、[v13](results/2026-10-31-bread-v13.json)、[v14](results/2026-10-31-bread-v14.json)。v13/v14 由 `9a5f622` 上的未提交工作树运行，JSON 记录 `workingTreeModified`、提示词版本和 SHA256；不能把父提交当成测试代码本身。

v14 增加不替用户编原因、接受纠正、避免 AI 内疚施压的约束，Anthropic 适配路径的温度与 OpenAI 路径一致设为 0.4。应用还为少量直接、明确的告别提供规则回复；引用故事、含请求和不明确前缀继续交给模型。单元测试覆盖误匹配边界。

| 观察 | v14 本次结果 | 仍有的差距 |
| --- | --- | --- |
| 明确道别 | “行，我去吃饭了，晚点再说。”直接得到“好，回头聊。” | 此条来自控制层；不能据此宣称模型学会了所有告别 |
| 接受纠正 | 不再用“我没说……”反驳，也没有把朋友定性为坏人 | “这个感受我接住了”仍像模板；另一次把“不是因为没拿到工作”简化成“不是工作的事” |
| 普通开心 | 不再把腿麻解释成小猫信任 | 用户还没说腿不能动，就补了一句“腿都舍不得动了吧” |
| 关系与自主权 | 没有“我过意不去”或要求用户照顾 AI 的负担 | “朋友那边费劲就少说两句”仍是未请求的建议；“绝交不用提上日程”回应过重 |
| 一个小动作 | 用户撤回请求后停止安排 | “扣下手机＋闭眼数呼吸”包含两个动作，没有严格满足只给一件事 |
| 未知与记忆 | 未编造室友名字；没有断言拒信由学历导致 | 这只能说明本例，不代表跨天记忆已存在 |

v14 的 16/16 请求成功，完整 JSON 响应中位 **1,165 ms**、nearest-rank p90 **1,477 ms**、最大 **2,576 ms**。其中一条规则道别是 **7 ms**，这些统计是整个应用接口的结果，不能全称为模型延迟。没有测首 token；v13 的中位为 1,200 ms、p90 为 2,316 ms。小样本和网络波动不足以证明版本间性能提升。

下一步仍是冻结更多未参与调参的中文多轮情境，再进行去标识的双人评审。当前没有对竞争产品进行同条件付费实测，也没有开展临床或心理健康效果研究。
